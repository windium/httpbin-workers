<p align="center"><strong>httpbin-workers</strong>: an <a href="https://httpbin.org">httpbin.org</a>-compatible HTTP request &amp; response service on Cloudflare Workers.</p>

<p align="center">
  <a href="https://deploy.workers.cloudflare.com/?url=https://github.com/windium/httpbin-workers"><img src="https://deploy.workers.cloudflare.com/button" alt="Deploy to Cloudflare"></a>
</p>

Every httpbin endpoint, reimplemented as a single dependency-free Worker. Responses match httpbin.org
down to the details clients notice: Flask-style JSON formatting (sorted keys, `", "` separators,
`\uXXXX` escapes), Werkzeug error and redirect pages, seeded `/bytes` output that is identical byte for
byte (a port of CPython's Mersenne Twister), Digest auth with `stale_after` and cookie handling, and
the same quirks in `/range`, `/response-headers`, `/status` and friends.

## Deploy your own

**One click:** press the button above. Cloudflare forks this repository into your GitHub account,
builds it and deploys it to `httpbin.<your-subdomain>.workers.dev`. Every later push redeploys it.

**From the command line:**

```bash
git clone https://github.com/windium/httpbin-workers.git
cd httpbin-workers
npm install
npx wrangler login
npm run deploy
```

To serve it from your own domain, add a [custom domain](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/)
to the Worker in the Cloudflare dashboard, or add a `routes` entry to `wrangler.jsonc`.

## Endpoints

| Group | Endpoints |
| --- | --- |
| HTTP methods | `/get` `/post` `/put` `/patch` `/delete` `/anything` `/anything/{path}` |
| Auth | `/basic-auth/{user}/{passwd}` `/hidden-basic-auth/{user}/{passwd}` `/bearer` `/digest-auth/{qop}/{user}/{passwd}[/{algorithm}[/{stale_after}]]` |
| Status codes | `/status/{codes}` (single code, or weighted list like `200:0.9,500:0.1`) |
| Request inspection | `/headers` `/ip` `/user-agent` |
| Response inspection | `/cache` `/cache/{n}` `/etag/{etag}` `/response-headers` |
| Response formats | `/brotli` `/deflate` `/gzip` `/deny` `/encoding/utf8` `/html` `/json` `/robots.txt` `/xml` |
| Dynamic data | `/base64/{value}` `/bytes/{n}` `/delay/{n}` `/drip` `/links/{n}/{offset}` `/range/{n}` `/stream-bytes/{n}` `/stream/{n}` `/uuid` |
| Cookies | `/cookies` `/cookies/set` `/cookies/set/{name}/{value}` `/cookies/delete` |
| Images | `/image` `/image/png` `/image/jpeg` `/image/webp` `/image/svg` |
| Redirects | `/redirect/{n}` `/relative-redirect/{n}` `/absolute-redirect/{n}` `/redirect-to` |
| Docs | `/` `/legacy` `/spec.json` (OpenAPI 2.0) `/apidocs` (Swagger UI) `/forms/post` |

All endpoints send permissive CORS headers, `HEAD` works wherever `GET` does, and `OPTIONS`/`405`
responses list the allowed methods, as in httpbin.

## Development

```bash
npm install
npm run dev        # http://localhost:8787
npm test           # starts a local Worker and runs the test suite against it
BASE_URL=https://httpbin.<your-subdomain>.workers.dev npm test   # ...or against any deployment
npm run compat     # diff a running instance against httpbin.org (default: localhost:8787)
npm run images     # re-render the PNG/JPEG/WebP images from assets/images/*.svg
```

`npm run compat [target] [reference]` sends 145 identical requests to both services and diffs status
codes, headers and normalised bodies. Current result against httpbin.org: **140 identical, 5 intentional
differences** (original artwork and text instead of httpbin's, see below).

### Project layout

```
src/
  index.js              Worker entry: registers routes and docs pages
  router.js             Werkzeug-style router (strict slashes, HEAD, OPTIONS/405, CORS)
  docs.js               Landing page, /legacy and OpenAPI spec, generated from the route table
  lib/
    json.js             Flask-compatible JSON (jsonify / json.dumps formatting)
    http.js             Response builders, Flask error/redirect pages, httpbin status_code()
    request.js          Request introspection (headers, args, body parsing, get_dict)
    random.js           CPython Mersenne Twister port for seeded /bytes and /stream-bytes
    cookies.js          Werkzeug-compatible cookie quoting and parsing
    encoding.js         base64 / hex / UTF-8 helpers
  routes/               One module per endpoint group
  content/text.js       Static bodies (/html, /json, /xml, /deny, /encoding/utf8, robots.txt)
  assets/images.js      Generated by `npm run images`
assets/images/          Source SVG illustrations (and rendered previews in dist/)
scripts/                Test runner, compatibility checker, image build
test/                   End-to-end tests (node:test), one file per endpoint group
```

## Differences from httpbin.org

- **Status codes** are limited to 200–599: Workers can't send 1xx codes or codes above 599.
- **Compression** is negotiated by Cloudflare's edge. `/gzip` and `/brotli` arrive encoded when the
  client's `Accept-Encoding` allows it. The edge never forwards `/deflate` as-is; it decodes it or
  re-encodes it as gzip/br. With `wrangler dev`, all three are sent exactly as encoded.
- `/cache`, `/etag` and `/range` add `Cache-Control: no-transform`. Without it, the edge compresses
  these responses and weakens their httpbin-style ETags to `W/"…"` or drops them.
- **Limits:** `/delay` and the `delay` parameter of `/drip` are capped at 10 seconds, and the `/drip`
  duration at 300 seconds. httpbin.org has no cap on `/drip`.
- **Original content:** the images, the ASCII art for `/deny` and `/status/418`, and the
  `/encoding/utf8` page are original. `/html` uses a shorter excerpt of the public-domain
  *Moby-Dick*. See [NOTICE.md](NOTICE.md).
- **Extra Cloudflare headers** (`CF-Ray`, `CF-Connecting-IP`, …) are hidden unless you pass
  `?show_env=1`, just as httpbin hides its own infrastructure headers.
